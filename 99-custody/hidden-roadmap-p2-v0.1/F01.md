# F01 — Structured migration planning

## Requirement

Add a read-only structured planning capability to the existing migration system.

The Python API must expose a public `MigrationPlanEntry` value type and a `Migrations.plan()` method. The CLI must expose the same information through a new `sqlite-utils migrate ... --plan-json` mode.

For a migration set, each plan entry must identify:

- migration set name;
- migration name;
- current status: `applied`, `pending`, or `stopped`;
- whether the migration is transactional, using `null` only when that information is unavailable for a legacy migration object;
- zero-based execution position within that migration set.

`Migrations.plan(db, stop_before=...)` must use the same `stop_before` interpretation as `Migrations.apply()`. A migration named by `stop_before` and every later migration in that set is reported as `stopped`.

`--plan-json` must work with the same migration-file and directory discovery accepted by the existing `migrate` command and must output one JSON array covering every discovered migration set in the order the current command would consider those sets.

## Acceptance

1. Planning an empty database reports all registered migrations as pending.
2. Planning a partially migrated database reports the existing applied migrations and remaining pending migrations correctly.
3. Qualified and unqualified `--stop-before` values produce the same stopping semantics as the existing apply path.
4. Unknown `--stop-before` values remain errors.
5. `--plan-json` does not create a missing database file.
6. Planning does not create, upgrade or otherwise modify `_sqlite_migrations`.
7. Migration functions are not executed while producing a plan.
8. Existing `migrate`, `migrate --list`, `migrate --verbose` and Python `Migrations.apply()` behaviour remains unchanged when the new planning interface is not used.
9. Existing legacy migration objects supported by the CLI remain usable; plan output may report `transactional: null` where the legacy object does not expose that property.

## Boundary

Do not add dependency ordering, plugin-provided migration sets, concurrency control or verification/audit behaviour as part of this requirement.
