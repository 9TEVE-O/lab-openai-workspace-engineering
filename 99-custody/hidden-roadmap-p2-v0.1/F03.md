# F03 — Concurrent migration application safety

## Requirement

Make migration application safe against two independent processes attempting to apply the same migration set to the same SQLite database at the same time.

For one database file, a migration identified by `(migration_set, migration_name)` must execute at most once even when two `sqlite-utils migrate` processes overlap.

Add a CLI option:

`--lock-timeout SECONDS`

with a default of `5.0`.

A contender may either wait for the active migration application to reach a safe state or terminate with a clearly identified migration-lock timeout error. It must never execute a migration that another process has already committed.

The protection must apply equally to migration sets loaded from files and, when enabled, from plugins.

The existing behaviour of transactional migrations remains: a failed transactional migration rolls back its changes and its applied record. Non-transactional migrations remain non-transactional; the new concurrency mechanism must not falsely record one as applied before its migration function has completed successfully.

## Acceptance

1. A deterministic two-process test uses a migration whose body performs a non-idempotent side effect inside the database and pauses long enough to force overlap.
2. After both processes finish, that migration's side effect is present exactly once.
3. `_sqlite_migrations` contains exactly one applied row for that migration.
4. The second process either succeeds after observing the committed migration or exits with the documented lock-timeout result.
5. A timed-out process makes no migration changes of its own.
6. If the first process fails a transactional migration, a later process can apply that migration successfully.
7. Existing single-process migration behaviour and output remains unchanged when no contention exists.
8. `--list` and `--plan-json` remain read-only and do not acquire a write lock merely to inspect state.

## Boundary

Do not add cross-set dependency ordering or a new distributed locking service. The control must remain local to the SQLite/database execution model.
