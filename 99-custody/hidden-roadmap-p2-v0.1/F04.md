# F04 — Dependencies between migration sets

## Requirement

Allow one `Migrations` set to declare that other migration sets must be completed first.

Extend construction of a migration set to support:

`Migrations("analytics", depends_on=("core", "identity"))`

Dependencies refer to migration-set names, not file names or individual migration names.

When multiple migration sets are supplied to the CLI, including opt-in plugin migration sets, the command must build one dependency graph before applying any migration.

Execution order must satisfy all declared dependencies. Where two sets are otherwise independent, preserve their pre-dependency discovery order.

The same ordered set graph must be used by:

- normal migration application;
- `--list`;
- `--plan-json`;
- `--stop-before`;
- verbose schema reporting.

`--plan-json` must expose the declared dependency names for every entry.

## Acceptance

1. A set declared later in discovery order runs first when another set depends on it.
2. Dependencies can cross from a file-provided set to an opt-in plugin-provided set and vice versa.
3. A missing dependency causes a non-zero result before any migration is applied.
4. A dependency cycle causes a non-zero result before any migration is applied.
5. Duplicate migration-set names across the combined discovery surface cause a non-zero result before any migration is applied.
6. For sets with no dependencies, existing discovery ordering is preserved.
7. `--stop-before` is evaluated against the dependency-ordered execution sequence without allowing a dependent set to run before an unmet dependency.
8. `--list` and `--plan-json` remain read-only.
9. The concurrent-application safety introduced previously still prevents duplicate execution after dependency ordering is resolved.

## Boundary

Do not add per-migration dependencies. Dependency edges exist only between named migration sets.
